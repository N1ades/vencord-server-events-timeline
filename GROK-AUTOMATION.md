# Инструкция для Grok Automation

Скопируй блок ниже в текущую автоматизацию. Передай ей значение `TIMELINE_TOKEN` в её закрытых настройках. Для инструмента, который умеет только открывать ссылки, подставляй этот секрет в параметр `token`. Если инструмент поддерживает заголовки, отправляй `Authorization: Bearer <TIMELINE_TOKEN>` и оставляй секрет вне ссылки.

~~~text
В конце каждого запуска обновляй общий календарь https://tl.nyades.dev/.

1. Получи существующие события через GET https://tl.nyades.dev/timeline/feed.
   В ответе JSON с массивом events. Используй id, start, url и status для сверки.
   Если календарь недоступен или ответ не JSON, отметь сбой в отчёте и отложи запись до следующего запуска.

2. По обычным источникам автоматизации найди новые события и изменения.
   Бери название, время, часовой пояс и статус из объявления организатора.
   Если точное время или часовой пояс неизвестны, укажи событие в отчёте как неподтверждённое.
   Укажи прямую ссылку на объявление без tracking-параметров.

3. Сопоставь событие с календарём. Сначала сверяй ссылку и дату. При переносе
   сверяй первоисточник, название, организатора и какое именно проведение перенесли.
   Для найденного события всегда используй существующий id, даже если дата поменялась.
   Для нового события выбери стабильный vrc-<организатор>-<идентификатор события>.
   Для Discord используй discord-<event_id> либо discord-<event_id>-<event_exception_id>
   для конкретного повтора, если эти идентификаторы есть в исходной ссылке.
   Отдельные повторы различай по исходному объявлению и дате проведения.
   Одно объявление может перечислять несколько разных дат. Если совпадение неясно,
   сообщи об этом в отчёте без автоматического создания второй карточки.

4. Для каждого подтверждённого события выполни отдельный GET на
   https://tl.nyades.dev/timeline с параметрами:
   token=<TIMELINE_TOKEN>, action=upsert, id, title, start, url, source=grok.
   Для существующей карточки сохраняй её source и group, включая записи Discord.
   Добавляй известные end, location, group (организатор), tags (через запятую),
   desc и priority (low, normal, high, rare). Для отмены используй action=cancel
   с существующим id и только при прямом подтверждении отмены организатором.
   Кодируй каждый query-параметр отдельно. Например, +03:00 в строке запроса
   кодируется как %2B03%3A00. start и end передавай в ISO 8601 с offset или Z.
   Не добавляй выдуманное время окончания. Отсутствующие поля оставляй без изменений.
   Для проверки ссылки без записи добавь dry_run=1.

5. Проверь JSON каждого ответа. Считай изменения по полю status только при ok=true.
   Если получил 429, 5xx или таймаут, повтори тот же запрос один раз.
   При 401 проверь настройку секрета. При 409 перечитай календарь и проверь id.
   HTTP-ошибки, HTML вместо JSON и dry_run не считай опубликованными событиями.

6. В отчёте покажи сколько карточек created, updated, unchanged и cancelled,
   какие записи не удалось отправить, и ссылки из поля url успешных ответов.
   Используй только публичные ссылки на карточки и https://tl.nyades.dev/.
   Секрет и ссылки записи с токеном в отчёт не включай.
~~~

Пример URL с заглушкой для секрета

~~~text
https://tl.nyades.dev/timeline?action=upsert&id=vrc-example-123&title=VRChat%20Meetup&start=2026-11-15T16%3A00%3A00%2B03%3A00&source=grok&url=https%3A%2F%2Fx.com%2Fexample%2Fstatus%2F123&tags=vrchat%2Cmeetup&dry_run=1&token=REPLACE_WITH_TIMELINE_TOKEN
~~~
