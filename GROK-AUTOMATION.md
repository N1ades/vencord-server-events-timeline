# Инструкция для Grok Automation

Скопируй блок ниже в текущую автоматизацию. Для записи подставляй `TIMELINE_TOKEN` из закрытых настроек в query-параметр `token`. Используй HTTPS.

~~~text
В конце каждого запуска обновляй общий календарь https://tl.nyades.dev/.

1. Прочитай GET https://tl.nyades.dev/timeline/feed. В JSON с ok=true возьми
   массив events. Для сверки используй id, url, start, status и recurrence.
   Если лента недоступна или ответ некорректен, отложи запись и сообщи об этом.

2. Найди новые события и изменения в обычных источниках автоматизации.
   Используй объявление организатора и прямую ссылку без tracking-параметров.
   Если точное время или часовой пояс неизвестны, укажи событие в отчёте
   как неподтверждённое.

3. Сопоставь событие с лентой.
   - Для обычного события сверяй ссылку и дату. При переносе перепроверь
     организатора, название и исходную дату, затем используй прежний id.
     Для новой разовой записи выбери стабильный vrc-<организатор>-<идентификатор>.
   - Все даты одной серии Discord относятся к discord-<event_id> из ссылки
     discord.com/events/<guild_id>/<event_id>. Поле recurrence.rule задаёт
     расписание, recurrence.exceptions содержит переносы и отмены отдельных
     дат, recurrence.history хранит завершённые даты.
   - Если ссылка Discord ведёт на конкретный повтор или лента содержит только
     старые записи discord-<event_id>-<occurrence_id>, считай их частью серии.
     Пропусти создание такой записи, даже когда базового id ещё нет в ленте.
     Если серия ещё не синхронизирована, укажи её в отчёте.
   - Для существующей серии Discord можно добавить подтверждённые метаданные,
     например tags, priority или location. Расписание, отдельные переносы,
     отмены повторов и историю обновляет расширение. Если нашёл изменение
     конкретной даты серии, сообщи о нём со ссылкой на объявление.
   - Для повторяющихся событий вне Discord без поддерживаемого правила
     укажи серию в отчёте. Публикуй отдельные даты только для самостоятельных
     событий, которые организатор объявил по отдельности.
   - При неоднозначном совпадении сообщи об этом в отчёте.

4. Отправляй записи через GET https://tl.nyades.dev/timeline.
   - Новое или перенесённое разовое событие: action=upsert, id, title, start,
     url и token=<TIMELINE_TOKEN>. Для новой записи укажи source=grok.
     Добавляй известные end, location, group, tags, desc и priority.
   - Для метаданных существующей серии: action=update, её базовый id,
     token и только подтверждённые поля, которые нужно изменить.
   - Для подтверждённой организатором отмены разового события: action=cancel,
     id и token. Для отмены всей серии Discord добавь series=1 и передай
     базовый id. Отмена одной даты не означает отмену всей серии.
   - Сохраняй source и group существующих записей, если эти данные не менялись.
     Передавай start и end в ISO 8601 с часовым поясом. Не угадывай окончание.
     Перечисляй tags через запятую. Значения priority: low, normal, high, rare.
     Кодируй параметры по отдельности. Например, знак + в +03:00 кодируется
     как %2B. Для пробного запроса добавь dry_run=1.

5. Проверь JSON ответа. Учитывай created, updated, unchanged и cancelled
   только при ok=true и без dry_run. Если API вернул другой id, используй его
   в следующих запусках. При 429, 5xx или таймауте повтори запрос один раз.
   При 401 проверь ключ. При 409 перечитай ленту. При series_managed проверь
   базовый id и не повторяй запись отдельной даты.

6. В отчёте покажи количество созданных, обновлённых, неизменённых и
   отменённых событий, а также записи, которые требуют проверки. Для
   ссылок используй публичные карточки /e/<id> и https://tl.nyades.dev/.
   Не выводи ключ и ссылки записи с token.
~~~

Пример пробного запроса для разового события

~~~text
https://tl.nyades.dev/timeline?action=upsert&id=vrc-example-123&title=VRChat%20Meetup&start=2026-11-15T16%3A00%3A00%2B03%3A00&source=grok&url=https%3A%2F%2Fx.com%2Fexample%2Fstatus%2F123&tags=vrchat%2Cmeetup&dry_run=1&token=REPLACE_WITH_TIMELINE_TOKEN
~~~
