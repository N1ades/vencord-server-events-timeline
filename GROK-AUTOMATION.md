# API таймлайна

Базовый адрес — https://tl.nyades.dev. Все запросы выполняются через HTTPS GET.

## Чтение

| Путь | Что возвращает |
| --- | --- |
| `/timeline/feed` | Все события в массиве `events` |
| `/timeline/latest?limit=25` | Последние изменённые события, до 100 |
| `/api/e/<id>` | Одно событие в поле `event` |
| `/e/<id>` | Публичная карточка события |

## Запись

Передавай параметры в URL запроса к `/timeline`. Ключ записи берётся из закрытых настроек и передаётся как `token`. Для чтения ключ не нужен.

| `action` | Действие | Параметры кроме `token` |
| --- | --- | --- |
| `upsert` | Создать или обновить. Действие по умолчанию | `id`, а для нового события также `title` и `start` |
| `add` | Создать событие | `id`, `title`, `start` |
| `update` | Изменить существующее событие | `id` и поля для изменения |
| `cancel` | Отметить событие отменённым | `id` |
| `delete` | Удалить событие | `id` |
| `touch` | Обновить время изменения | `id` |

- **`id`** — стабильный идентификатор из латинских букв, цифр, дефисов и подчёркиваний, до 128 символов. Первый символ — буква или цифра. При переносе используй прежний ID.
- **`start` и `end`** — ISO 8601 с часовым поясом или Unix-время в секундах либо миллисекундах. Пустое `end=` очищает время окончания.
- **`title`, `desc`, `location`, `url`, `source`, `group`** — название, описание, место, ссылка на источник, источник данных и группа или организатор.
- **`tags`** — теги через запятую. **`priority`** — `low`, `normal`, `high` или `rare`. **`status`** — `scheduled`, `active`, `cancelled` или `completed`.
- При обновлении передавай только изменившиеся поля. Для валидации без записи добавь `dry_run=1`.
- Кодируй каждый параметр отдельно. Например, знак `+` в часовом поясе передаётся как `%2B`.

## Пример

~~~text
https://tl.nyades.dev/timeline?action=upsert&id=community-meetup-123&title=Community%20Meetup&start=2026-11-15T16%3A00%3A00%2B03%3A00&source=grok&dry_run=1&token=REPLACE_WITH_TIMELINE_TOKEN
~~~

## Как использовать в автоматизации

1. Прочитай ленту и сопоставь события по ID, исходной ссылке и дате. Сначала проверь, есть ли уже запись или серия, к которой относится событие.
2. Запиши подтверждённые изменения. Для новых событий используй стабильный ID. Если дата уже входит в опубликованную серию, отдельную запись для неё не создавай.
3. Проверь JSON. При `ok: true` используй `status` (`created`, `updated`, `unchanged`, `cancelled`, `deleted` или `touched`). Если ответ вернул другой `id`, используй его в следующих запросах. Ответ с `dry_run: true` означает проверку без публикации.
4. При `401` проверь ключ. При `409` перечитай ленту и сверяй ID. При `429`, ошибке `5xx` или таймауте повтори запрос один раз. В отчёт выводи результаты и публичные ссылки на карточки. Ключ и ссылки записи с токеном оставляй в закрытых настройках.
